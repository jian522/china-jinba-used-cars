## 2026-08-28 下午：API 推送绕过网络封锁，UI v5 上线验证通过

- **推送阻塞**：Clash 代理 127.0.0.1:7890 已死但环境变量 HTTP_PROXY/HTTPS_PROXY 仍注入（WORKBUDDY_PROXY_SOURCE=system）；git push 走代理连不上。`env -u` 绕过代理后直连 github.com 也被墙（Connection reset），但 **api.github.com 可达（200）**，SSH 22 端口也通但无公钥。
- **解决方案（GitHub REST API 推送）**：从 `~/.git-credentials`（store helper）提取 jian522 的 40 位 token，用 Git Data API 四步推送：POST /git/blobs（29 个文件，文本 utf-8 / 二进制 base64）→ POST /git/trees（base_tree=远端父提交树）→ POST /git/commits（parent=34439160）→ PATCH /git/refs/heads/main（先校验非快进）。
- **关键坑**：
  1. urllib 必须加 `User-Agent` 头，否则 GitHub API 返回 404（不是 401！极难排查）
  2. `urllib.request.install_opener(build_opener(ProxyHandler({})))` 绕过系统代理
  3. API 端点不支持短 SHA，必须用完整 40 位 SHA
  4. diff 中**被删除**的文件不能当 blob 传（脚本 v1 曾把删除当空文件新增），第二脚本用 `{"path":..., "sha":null}` 树条目删除修正
  5. GitHub API 对 ~750KB 的 trees?recursive=1 响应会 IncompleteRead，需重试循环
- **验证**：最终远端树 SHA `6ecffff2` 与本地 `git ls-tree -r`（用 `-z` 字节模式避免中文转义假差异）完全一致，2005 文件 TREE_MATCH_OK。远端 main = 4860e250。
