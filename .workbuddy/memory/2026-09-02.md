### 本次踩到的坑（重要，避免重犯）
1. **后台任务会被掐网**：`run_in_background=true` 跑长任务，线程静默挂起 13 分钟、0 请求、timeout 也不触发。**长推送必须前台分批跑**，每批控制在 ~100 秒；被 auto-background 后反而能跑完（4 批 720 个 OK），所以策略是前台启动、容忍它转后台。
2. **本地 `origin/main` 引用不可信**：它指向只有 1232 文件的旧提交（真实远程 2051 文件），据此算 diff 会得出 773 MB / 2941 文件的错误结论。**base 必须走 API**：`GET /git/refs/heads/main`。
3. **单次建树 2210 条目必 502**：改链式分批建树，`base_tree` 用上一批结果，每批 `TREE_CHUNK=400`。
4. **`/rate_limit` 是根端点**，不在 `/repos/{repo}` 下，拼了 BASE 前缀会 404；它自身不消耗配额，不能用来估算已发请求数。
5. **偶发失败要能重试**：实战中每批 1~7 个失败（401 Bad credentials / 400 malformed / Remote end closed），重跑一次基本全过，靠缓存跳过已完成项。
6. **本地网络波动会伪造"线上故障"**：曾出现图片 IncompleteRead、连 speed.cloudflare.com 的 1MB 对照文件也失败、同一 sitemap 时好时坏 → 凡遇下载截断，**先做外部对照实验**再判断是否站点问题。上传完整性用 `git hash-object` 与 `GET /contents/{path}` 的 sha 比对（本次 2164 文件抽样全部一致）。
